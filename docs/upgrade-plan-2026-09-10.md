## 1. Phase 0 — 미커밋 WIP 정리 (선행)
- `npm run verify`(tsc·test·audit·lint) 통과 확인 → 별도 커밋 `fix(questions): 조사 해소·최장보기 편향 교정`.
- 실패하면 원인 고친 뒤 커밋. 이후 작업과 섞지 않는다.

## 2. Phase 1 — 단원 체계 재편 (학기 + 5-2 역사)
- **데이터 모델**: CURRICULUM_UNITS 를 `{ grade, subject, semester: 1|2, units[] }` 로 확장. 기존 문항의 `unit` 문자열은 그대로 두고, 단원→학기 매핑 표를 추가(문항 데이터 무이동).
- **5학년 사회 2학기 = 역사 단원 신설** (2022 개정 교육과정·검정 교과서 편제를 **출처 확인 후** 확정. 기억으로 쓰지 않는다 — HARD 규칙). 후보 구조: 선사~고조선 / 삼국·통일신라·발해 / 고려 / 조선 전기 / 조선 후기 (4~6단원). 기존 보충 「역사 인물과 사건」 60문항은 alias 로 새 단원에 재배정.
- **6학년 사회** 단원(일제강점기·광복·민주화·정치·세계)도 같은 출처로 1·2학기 배정 재확인.
- **UI**: 게임 설정·문제 목록·문제 만들기 모두 「학년 → 학기 → 과목 → 단원」. 학년군 묶음(5-6)은 유지하되 **선택 학년의 학기 단원을 먼저**, 다른 학년 단원은 접힘 「학년군 다른 학년 단원」으로.
- 검증: `audit-questions.mjs` 에 「학기 미배정 단원 0건」 게이트 추가.

## 3. Phase 2 — 문제 증량
- 기준선: 교과서 단원당 **최소 100문항**(현재 최소 60). 신설 역사 단원은 0 → 각 120 이상.
- 생산 경로: 웹 브릿지 `--batch` 1회(JSONL, `--chat-every 12 --gap 20`) → `questionSanitizer` → `audit-questions`(정답 유일성·중복·최장보기 편향 ≤35%) → FULL 사실 교차검증(역사 연도·인명은 📅 date-claims 게이트).
- 산출: `src/data/seed-2022-grade5-history-*.ts` + 얇은 단원 보강 파일. 증량 후 총계·단원별 표를 커밋 메시지에 기록.

## 4. Phase 3 — 문제 만들기 UX
- 단원 **선택 사항**으로: 비우면 `unit: ''` 저장 → 목록/게임에서 「단원 없음」으로 표시·필터. 게임 설정에서 「내 문제(단원 무관)」 소스 추가.
- 모달: 오버레이 클릭 닫힘 **제거**. 닫기 = X 버튼·ESC·취소만. 입력이 있으면 「작성 중인 문제를 버릴까요?」 확인.
- 초안 자동저장(localStorage, 1초 debounce) → 실수로 닫거나 새로고침해도 복구.
- 회귀 테스트: `questions/create` 에 대한 브라우저 시나리오(입력 → 바깥 클릭 → 내용 유지).

## 5. Phase 4 — 타이포·UI 디자인 (design-master 공정)
- **폰트**: Black Han Sans 를 본문·문제 텍스트에서 제거. 제목 전용 1종(Pretendard 800 또는 Noto Sans KR 900)·본문 Noto Sans KR 400/500. `subsets` 에 korean 추가·`display: swap`. 특수문자 폴백 실측(½ × ÷ · ㉠ ㉡ 원문자) 스크린샷 before/after.
- **굵기 다이어트**: `font-black` 107곳 → 제목·점수 등 강조 12곳 내외만 유지, 나머지 `font-semibold`/`font-medium`. 문제 본문은 500.
- **디자인 시스템**: 브리프 → 테마 3안(전자칠판 원거리 가독 기준: 최소 본문 28px·대비 4.5:1) → 토큰(globals.css) → 적용 → 결정론 게이트(대비·최소 글자 크기·터치 타깃 44px) + 교차검증.
- 범위: 대시보드·게임 설정·문제 관리·게임 화면(display/play) 4축. 기능 로직은 손대지 않는다.
